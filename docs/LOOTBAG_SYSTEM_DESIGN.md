# Lootbags: native ELB tables and hidden global allowances

Current architecture, 2026-10-04. This replaces the earlier standalone importer/planner
proposal committed as `ea76683`; Git history retains that proposal. ELB 1.3.5 owns
XML parsing, table objects, weighted selection, Fortune/trash merging, native player
limits, stack splitting, delivery, sounds and bag consumption.

## Loading and audit

`MixinLootGroupsHandler` wraps the `VerifyConfig` call inside `ReloadLootGroups`.
After ELB has built and validated a full local table collection, `LootLoader.patch`
runs named `LootModule`s on those actual objects, before they become live tables.
The XML file is never rewritten. Header-only server configuration packets are not
treated as full local tables and are not patched.

`NativeLootTables` stages edits against native `LootGroup`/`Drop` objects. It supports
replacement, fixed amount, weight, addition and removal. Exact targets require the
group, native entry identifier and registry identity/metadata. Replacements preserve
NBT, native player caps, groups and other fields unless explicitly changed. A module
validates its targets before commit and verifies the resulting invariants.

The ME Controller module requires exactly the two known source entries:

| Group | Source ID | Required input | Output |
| --- | --- | --- | --- |
| AE Basic, 37 | c86156c4-b72c-4ada-9ad2-3bbb229c5664 | 1, fixed | 1 |
| AE Good, 38 | 13a284df-df59-4389-8543-9c3b65fc28dc | 4, fixed | 1 |

Weights remain positive and unchanged. Additional/missing/ambiguous controller
sources, changed expected amounts or failed postconditions are integrity failures.
`MODIFY_ME_CONTROLLER_LOOT` expects exactly one modification: Basic is validated,
Good is changed. `VERIFY_NATIVE_LOOT_TABLES` checks that the load hook ran exactly
once, verifies the published tables at load-complete, checks native weight totals
and resolves the actual controller stack after item registration is complete.

Startup uses the existing `AuditManager` session. Later file reloads use a fresh
`AuditSession` with the same typed scopes and count contracts, so they do not try
to reopen a finished startup session. Failed patch exceptions are rethrown outside
ELB's catch block: no fallback sample table can hide a broken patch.

## Weights and caches

After editing, sum weights are recomputed with `LootGroup.updateMaxWeight`; negative
weights, invalid amounts and integer overflow fail validation. ELB publishes the
new collection and clears `_mBufferedLootGroups` itself. Future Fortune/trash pools
are generated by ELB from the patched source objects. We have no parallel catalog
or Fortune cache. The integration fixture warms a merged pool before reload and
requires a new correctly patched pool afterwards.

`/lootbags reload` and `/lbag reload` use this audited path. The command reports
failure correctly (the upstream command prints success even when reload returns
false). Native addloot/addinventory/addgroup commands are blocked because they
mutate already-live tables outside the load transaction; edit XML and reload instead.

## Hidden global limit

`ServerLootRuntime` surrounds the native right-click to establish a server-thread
context. Narrow mixins:

1. Reject exhausted global rewards before ELB updates its own per-player counters.
2. After ELB materializes a selected stack, durably claim its allowance before it
   can be spawned. This second check also covers repeated/bundled sources.
3. Observe ELB's spawn result and record delivered/failed outcomes afterwards.

`GlobalLootLimits` owns only allowance checks and durable claims. The built-in
`gtnhextranerf:me_controller` allowance permits one controller per save, shared by
all players, bag types, Fortune variants and dimensions. It is random, not guaranteed.
Native ELB reroll/exhaustion behavior remains intact, including its ten attempts
and not consuming a bag when a draw produces no available reward.

The allowance is never sent to clients, added to tooltips, or used to remove entries
from preview tables. Once spent, the item stays listed as a potential native reward.
Only generic operational errors may be shown to a player; allowance failures are
handled as an unavailable native selection, without a custom limit message.

## Save compatibility and failures

`FileLootLedger` remains at `<save>/data/gtnhextranerf/loot/claims.journal`. The v1
format, stable controller key, checksums, sequence validation, exclusive file lock
and force-before-delivery contract are preserved. A checked-in v1 fixture proves
that controller and native-player counters written by the previous engine survive.
Corrupt/missing journal files in an existing ledger directory are never recreated.

Only globally limited rewards create new records. Ordinary openings no longer grow
our journal. A failed or uncertain delivery never refunds or replays a claim.
Completed/pending historical records remain readable; automatic compaction and
administrative recovery are not introduced by this refactor.

ELB again owns its YAMCore per-player database. An adapter preserves the maximum
of its native count and any older `elb-player/...` count already in our journal.
The native DB handle is reset on server start/stop so two saves cannot share the
previous handler's database. Global runtime/ledger state is also recreated per save.

Claims only cover issuance after installation. Existing inventories, crafting, quest
rewards and unrecorded historical ELB drops are not counted retroactively. Disk
force is used; no claim is made about physical power-loss guarantees beyond that
platform contract. Mid-force device failure has not been injected.

## Client behavior and extension scope

The same full-file load hook runs on the physical client. NEI reads those patched
native tables, so it sees one controller. ELB's own server packet contains group
metadata without drop lists; it does not synchronize arbitrary server-only XML
edits. Client and server pack configurations must match, as before. No new client
packet or NEI handler is needed for the built-in quantity change or hidden limit.

Add ordinary balance changes as `LootModule`s in `LootLoader` with a typed audit
scope, exact target expectations, mutation counts and a verification method. Keep
hidden global rules separately in `GlobalLootLimits` definitions at runtime startup.

The former standalone percentage-per-opening and first-opening-guarantee APIs were
removed with their custom planner. They are not active features of this native
adapter. If requested for a concrete item later, implement them as explicit server
extensions; do not restore a duplicate implementation of ELB's normal selection.
